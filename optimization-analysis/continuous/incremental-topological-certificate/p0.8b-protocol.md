# P0.8b append-stable topological certificate refinement

P0.8b retains the semantic and formal performance gates in `experiment-protocol.md`,
except that a short certificate no longer falls back before attempting validation and
the selected-program performance pilot is no longer an advancement gate.

## Exact refinement

When stable event IDs grow from `N` to `M`, extend the provisional rank vector with
`rank[i] = i` for each newly appended ID `i` in `[N,M)`. Every rank previously produced
by the complete DFS is a permutation of `[0,N)`, and earlier append extensions preserve
that invariant. Therefore new ranks are unique and strictly after all retained ranks.

The extension alone proves nothing. The evaluator must still enumerate every current
edge `(u,v)` in the exact lazy root and require `rank[u] < rank[v]`. If any edge fails,
the retained complete lazy DFS runs and either publishes a fresh exact order or reports
its exact cycle witness. If `M` exceeds the uint32 rank range, extension fails closed to
the complete DFS.

Rollback may leave a longer vector containing inactive stable IDs. Its restriction to
the active subgraph remains a valid strict order after edge deletion. If a later branch
reactivates those IDs, every edge is validated again, so stale branch placement cannot
publish an acyclic verdict.

## Changed cost model

- Extra time on growth: `O(M-N)` scalar appends before the existing exact edge stream.
- Hit opportunity: old-to-new append edges such as program order can now preserve the
  certificate and skip color/parent initialization plus DFS control work.
- Miss cost: the same validation prefix plus complete fallback as P0.8a.
- Persistent space remains `4*M*C`; no new field, edge cache, undo or checkpoint state.

## Additional correctness gate

Before the formal matrix, the focused unit test must show a universe-growth insertion
that keeps full `lazyCycleChecks` unchanged, followed by a non-forward edge that
increments it through exact fallback. All P0.8a correctness gates must then be repeated
because this changes certificate reuse behavior.
