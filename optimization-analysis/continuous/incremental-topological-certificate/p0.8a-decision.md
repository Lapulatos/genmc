# P0.8a opportunity decision

Decision: reject the short-certificate fallback as an effective incremental strategy;
do not run its full six-repetition pilot or formal matrix.

## Evidence

- Correctness gates passed: Release 159/159, GCC 13 ASan+UBSan 5/5, mutation oracle
  39 rows / 5,441 comparisons, and broad differential 852 matches + 12 mutually
  unsupported + 0 mismatch over 864 pairs.
- The first complete paired pilot repetition has zero status, category, execution,
  snapshot or base mismatch and zero coverage loss.
- TSO fib, TSO queue and PSO queue each report candidate/baseline full lazy-check ratio
  exactly 1.0. Thus this implementation avoids zero complete DFS checks on the affected
  deterministic one-worker workloads.
- The cause is structural: almost every useful insertion grows the stable event universe,
  while P0.8a treats a certificate shorter than the new universe as invalid before
  checking any edge.
- One PSO queue RSS observation is 1.038667, already above 1.02, although a single
  repetition is insufficient to attribute that process-level variation.

Because full-check counts are deterministic for the same complete exploration and the
opportunity gate requires at least a 20% reduction, five more repetitions cannot make
this implementation pass. The partial run was stopped rather than spending another
roughly ten minutes. Raw partial XML/logs are under `server-results/pilot-p0.8a/`.

The exact P0.8a source/test diff is archived as `p0.8a-source.patch`. P0.8b refines only
universe growth: append new stable IDs at strictly increasing provisional ranks, then
validate every current root edge exactly. It does not add model selection or trust an
unvalidated order.
