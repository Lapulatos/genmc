# SC candidate-equivalence quotient decision

## Decision

Revise; do not retain the current SC RVF implementation as an optimization.

The implementation passes the bounded correctness gates and reduces the enabled 185-case
litmus cohort by 25 complete executions (1,308 to 1,283). It does not activate on any task
in the formal adapted SV-COMP workload, so the full workload has no candidate-space
reduction. Broadening the static gate merely to obtain benchmark coverage is not justified
without extending the completeness argument for abort/property lowering, mutex operations,
loops and non-atomic accesses.

## Correctness evidence

- local unit/property suite: 176/176;
- server Release focused suite: 13/13;
- server GCC 13 ASan+UBSan focused suite: 13/13;
- generated reachable-state oracle: 20 shapes, one/two workers, 6,480 calls, zero state,
  verdict, worker, timeout or late-fail-open difference;
- sanitizer generated oracle: four shapes, 648 calls, zero difference or sanitizer report;
- automatic differential: 740 rows over 185 fixtures, zero invariant violation;
- mutation oracle: 39 rows / 5,441 full recomputations;
- broad differential: 864/864 matches, zero mismatch and zero unsupported pair.

## Formal workload

The valid SC matrix contains 3 x 725 cells (baseline, quotient-disabled control and RVF),
with one 48-worker dynamic queue per configuration. Of 725 listed tasks, 611 are not
adapted by the fair-coverage tool and 114 execute. All three configurations have the same
status distribution: 67 TRUE, 23 FALSE, 16 TIMEOUT, seven compilation errors and one
unsupported-property error.

Baseline, control and RVF are identical on:

- verdict/category for all 725 rows;
- complete executions: 120,187 each;
- every recorded RF/CO/backward/work/validity counter;
- every per-task complete-execution count;
- control versus baseline native search counters (zero mismatch).

RVF activates on zero formal tasks. The 106 gate-bearing executions fail open for external
`abort` (53), modeled mutex lock (40), non-atomic store (8), loop (4), or non-atomic load
(1); eight compilation/property rows have no gate record. Consequently RVF records zero
loads attempted, VerifySC calls, representatives and reduced loads on this workload.

On the 90 common solved rows, task-bootstrap ratios are:

- RVF/baseline CPU 1.00281, 95% CI [0.99650, 1.00864];
- RVF/baseline wall 0.99556, 95% CI [0.96314, 1.01884];
- RVF/baseline RSS 0.99951, 95% CI [0.99856, 1.00021];
- control/baseline CPU 1.00644, 95% CI [0.99810, 1.01624].

These are zero-activation drift measurements, not quotient performance measurements.

The corrected unchanged controls also complete 725 rows each. TSO records 120,187 complete
executions. PSO-V9 records 94,937 and the expected smaller preventive-pruning search totals;
they are environmental controls, not evidence for the SC quotient.

## Invalid launches excluded

Three zero-task starts were excluded before the valid matrix: an incorrect container disk
path, a missing historical `/workspace` mount, and missing host cgroup mounts. The first
complete process also produced invalid TSO/PSO cells because its wrapper attempted to
replace a backend token already expanded by the fair adapter; the valid SC cells were
retained, and TSO/PSO were rerun with explicit expanded model-path replacement.

## Next direction

Do not spend another formal matrix on the current narrow RVF gate. Preserve the prototype,
proof notes and exhaustive oracle as research evidence, but return optimization effort to
the retained V9 RF-DPOR/CAAT path. The next candidate should remove candidate subtrees on
the actual full workload, with the previously frozen bounded positive conflict-core design
as the first option. It must pass the same correctness gates before formal measurement.
