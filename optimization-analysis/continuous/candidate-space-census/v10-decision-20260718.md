# V10 bounded positive conflict cores: reject

## Decision

Reject V10 and do not retain `--cat-conflict-cores` in the next optimization
baseline. The valid complete 725-task actual workload shows no exploration
reduction and a material CPU regression. The earlier 96-task matrix is only a
mechanism diagnostic; it is not used for this decision.

## Correctness evidence before the actual workload

- Local CTest: 194/195 pass; the sole failure is the pre-existing missing
  `scripts/run-parallel.sh`. The ten-iteration randomized driver passes.
- Server GCC 13 Release: 185/185 CAT/CAAT/unit/property tests pass.
- Server GCC 13 ASan+UBSan: 14/14 V10-focused tests pass with halting leak and
  undefined-behavior settings.
- V10 mutation oracle: 39 rows and 5,658 full recomputations, zero mismatch.
- V10 broad differential: 288 programs × SC/TSO/PSO = 864 matches, zero mismatch.

## Full 725-task actual-workload result

The server ran V9 and V10 concurrently over the identical 725 adapted
SV-COMP `unreach-call` PSO tasks, with 60 CPU seconds and 4 GB per task. V9
used cores 0–23 and V10 cores 28–51. The two adapters used independent rewrite
roots. Both BenchExec method units exited zero; the result contains both XML
files and both log archives.

- V10 has conflict-core hits in 158/725 tasks: 14,193,035 hits, 4,383,344 RF
  and 9,809,691 CO core prunes.
- `conflict-core-direct-checks-avoided=0`. Thus all hits merely reproduce a
  V9 rejection; no selected root is avoided and no accepted subtree is removed.
- Four V9 `false(unreach-call)` tasks are V10 timeouts at about 61 s. A fifth
  V10 task finds the false result but crosses the time limit and is categorized
  as `TIMEOUT (false(unreach-call))`. These are performance regressions rather
  than a changed completed verdict. Among all 368 tasks completed correctly by
  both variants, status, complete executions and every search counter match.
- Among 368 tasks terminal and correct under both variants, V10/V9 CPU is
  1.049916 with task bootstrap 95% CI [1.025769, 1.077275]; wall time is
  1.048947 [1.024901, 1.076183]; RSS is 1.000341 [0.999941, 1.000849].

The CPU CI upper bound fails the frozen below-1 retention condition, while RSS
is within the 1.02 bound. The completed-task timeouts and zero direct-root
saving are independently sufficient to reject V10.

## Why the direction is rejected

The data confirms the design limitation: a V10 core is learned only after V9
has rejected an individual RF/CO candidate. On a hit it avoids some repeated
candidate-level proof work, but the checker still executes the preventive root
for the surrounding choice point and reaches the same accepted search space.
The 8.60 billion exact-literal probes and clause maintenance therefore add cost
without an exploration-space reduction.

The next candidate must cut an inconsistent prefix/subtree at its earliest
rollback-safe decision level, or prove equivalence of multiple *consistent*
RF/CO continuations. Re-running V10 cannot address this structural limit.
