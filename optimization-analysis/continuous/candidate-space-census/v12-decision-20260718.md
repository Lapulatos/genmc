# V12 exact structural cursor decision

## Decision

Reject the production V12 structural indexes and restore the previous exact scans.
Keep the correctness property, launch/analyzer scripts, and raw evidence.

## Candidate

V12 added immutable indexes to structural `Relation` values so
`nextSuccessor()`/`nextPredecessor()` could enumerate exact thread-group, location,
initial-event, and active-event slices. It changed enumeration only: CAT membership,
V9 preventive pruning, accepted candidates, and equivalence classes were unchanged.

The same-source comparison used these frozen server binaries:

- before (`GENMC_DISABLE_EXACT_STRUCTURAL_CURSORS`): `88d5fbfd5a4e293b1b9946f2d23c92ddeb46923423455913b32e0742a93e76b5`
- after: `b5f6132bef6d8b54282499c011ecec14cb4f2982c5af3367d36926cb7e3b7fdc`

## Correctness and completeness evidence

- Randomized cursor property: all four structural kinds, both directions, every event,
  and every lower bound agree with an exhaustive `contains()` scan.
- GCC 13 ASan+UBSan: 8/8 focused checks pass with no diagnostic.
- Broad differential: 864/864 recursive-PSO pairs match; zero mismatch and zero
  unsupported.
- Two full repetitions: 725 tasks per side per repetition, 2,900 result rows total.
  Both launch units exit zero in both repetitions.
- Across both full repetitions: zero status/category differences, zero completed-
  execution differences among common-correct tasks, zero common-correct search-counter
  differences, and zero completed-to-resource transitions in either direction.

This exact-count oracle is valid because V12 is search-preserving. It must not be reused
unchanged for a future coarser-equivalence/quotient optimization, where fewer executions
may be intentional and completeness needs an outcome/representative-coverage oracle.

## Cost and benefit

Single-run task-clustered ratios (after/before):

| Run | CPU | 95% bootstrap CI | Wall | 95% bootstrap CI | RSS |
|---|---:|---:|---:|---:|---:|
| A | 0.988710 | [0.977375, 1.001604] | 0.989603 | [0.978159, 1.002127] | 1.000179 |
| B | 1.006793 | [0.995481, 1.019709] | 1.006638 | [0.995120, 1.019659] | 1.000167 |

Using per-task medians across A/B for the 373 tasks completed correctly by both variants
in both repetitions:

- CPU: `0.998008 [0.988150, 1.009684]`
- wall: `0.998314 [0.987935, 1.010209]`
- RSS: `1.000173 [0.999945, 1.000453]`

All preventive-pruning totals are exactly equal, including 1,205,405 direct checks,
16,119,624,922 base candidates, and 2,943,514,438 emitted edge candidates. This confirms
the same work/search protocol, but the indexed cursor does not provide a reproducible
end-to-end saving. The median CPU point estimate is only 0.20% lower, its interval spans
roughly -1.18% to +0.97%, and RSS has a small positive point estimate.

## Resulting direction

Do not spend another repetition on V12: the two runs bracket 1 and the combined interval
shows no decision-relevant benefit. The next candidate should remove candidate executions
or equivalence classes with a dedicated completeness oracle, rather than add another
index to the existing exact traversal.
