# P0.2 exact positive rejection-kernel cache protocol

Date frozen: 2026-07-16

## Semantic boundary

- The cache is worker-local and enabled only by `--cat-kernel-cache`.
- Certified SC/TSO candidate profiles do not construct it; their hot path is unchanged.
- A hit requires every positive base literal of one complete `Reasoner` explanation in
  the current `StableGraphSnapshot`.
- Negative/difference explanations, empty reasons, failed explanations, and kernels
  beyond the 4,096-entry bound fail closed to the complete evaluator.
- A miss always runs the existing synchronization and incremental/offline evaluator.
- `--cat-oracle` recomputes cache hits and asserts that the full result is rejected.
- No built-in SC/TSO consistency checker supplies a cache result.

## Expected cost changes

| Step | Expected effect |
|---|---|
| Stable graph materialization | unchanged; required before lookup |
| Kernel lookup | added linear subset-test cost on generic candidates |
| Graph synchronization | removed on a hit |
| Incremental/offline fixed point | removed on a hit |
| Reason construction | paid only after a rejected miss; duplicates that hit are never re-explained |
| Deletion minimization/replay | removed entirely |
| History/checkpoint memory | no new checkpoint on a hit; kernel vector adds bounded worker-local memory |
| Candidate/interpreter work before consistency | unchanged in P0.2; earlier RF/CO hooks are deferred |

## Gates

1. Release unit/property and CLI tests pass.
2. Mutation suite performs all 5,441 Phase-2 oracle checks and explicitly recomputes hits.
3. Broad SC/TSO/PSO differential has zero comparable status/signature/execution mismatch.
4. Four paired repetitions on the established 96-task sample use one core/task, 4 GB,
   60 seconds, 48 task workers, disjoint core groups, and balanced group swapping.
5. Retain only with zero opposite terminal verdict or safe execution-count mismatch and
   aggregate task-cluster CPU 95% CI below one. Resource-limit improvements are reported
   separately and cannot conceal a common-solved regression.

## Interpretation limit

P0.2 can remove repeated invalid generic PSO candidates after stable materialization.
It cannot fix OOM before the first consistency query, reduce the number of valid
executions, abstract local loops/values, or provide property-directed pruning.

## Pre-outcome topology amendment

The initial launcher requested three repetitions, which assigns one physical core group
twice to one variant. SC repetition 1 is a negative control because the cache is not even
constructed for a certified profile; its visible 2--3% side difference exposed the core
imbalance before any PSO result was inspected. A fourth swapped repetition is therefore
required so each variant uses each core group exactly twice. The decision statistic uses
the median of all four repetitions; no repetition is selected or discarded.
